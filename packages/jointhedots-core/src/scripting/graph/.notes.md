
# Scripting graph


## Execution model des functions

Two kind of execution model:
- __Sequential__ Mode
- __Dataflow__ Mode

Execution d'une function:
- Sequentiel: les noeud sont executé un par une par: node.apply(ctx)
- Dataflow: execute les noeud comme une fonction sequentiel, qui active les task du dataflow, puis le context reste actif en arriere plan et met a jour les tasks lors des changements d'input par task.update(ctx)

Retour d'une function:
- Sequentiel: retourne une Promise<T> ou la valeur <T>
- Dataflow: retourne un Pipeline<T> des valeurs futures


## Entité des functions

Types d'entités principale:
- __Node__: propose un apply qui permet d'executé et récupérer une valeur associée
- __Task__: propose un init et update qui permet d'executé et mettre a jour ses sorties/ ou emettre sur ces pipelines
- __State__: permet de stocké un état dans le context d'execution

Execution des d'imbrications d'elements:
- Les imbrications doivent etre executer par leur Use
- L'execution doit passer par l'appel des Use

Les elements orienté dataflow doivent avoir enregister un object Task, qu'il peuvent activer durant le apply

TO-THINK: Le read est peut etre redondant au apply (a reflechir), avec l'encapsulation de l'update dans une Task, les noeuds sont tous similaires au expressions.
TO-THINK: Lié les noeuds pour le apply n'est probablement plus necessaire, juste l'appel du Use doit suffir.

## Task scheduler

- __Use__: Gere la consommation de valeur produite par un autre noeud

Type de uses:
- __UseValue__
- __UseList__
- __UseAggregate__:

## Canal de transmission des données entre entités d'une function

Type de structure de canalisation:
- __Pipeline__: encapsule la gestion d'une suite de valeur future
- __Promise__: encapsule la gestion d'une unique value future (cas particulier du pipeline)
- __Value__: pas d'encapsulation c'est la valeur prete à consommer
